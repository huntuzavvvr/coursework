# Mosaic

**Функциональный язык, в котором результат — картина возможных миров.**

Обычная программа вычисляет одно значение. Mosaic может вычислить точное
распределение значений, исключить сценарии, не согласующиеся с наблюдением,
и показать решения, приведшие к каждому результату. При этом функции,
замыкания и списки остаются обычными инструментами программирования.

```lisp
(let [weather (fn [ignored]
                 (choose "weather" [[3 "sun"] [1 "rain"]]))]
  [(weather 0) (weather 0)])
```

```text
["rain" "rain"] @ 1/4
["sun" "sun"] @ 3/4
evidence = 1; worlds = 2
```

Имя `weather` задаёт одно событие внутри мира: второе обращение сохраняет
первый выбор. Для независимых событий нужны разные имена. Никакого случайного
генератора здесь нет — интерпретатор точно перечисляет конечные варианты.

## Запуск

Нужен [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0), включающий
F#. Дополнительных NuGet-зависимостей, кроме FSharp.Core из SDK, нет. Для
сквозных тестов нужен Python 3.10 или новее; базовые F#-тесты его не используют.

Из корня этого проекта (`mosaic/`):

```sh
./mosaic run examples/factorial.mos
./mosaic run examples/detective.mos --explain
./mosaic run examples/queens.mos --json
./mosaic eval '(sum (range 1 11))'
./mosaic repl
./scripts/verify.sh
```

Команда `./mosaic` собирает CLI в Release и запускает его. Диагностика сборки
идёт в stderr, результат программы — в stdout. Скрипты выбирают `DOTNET`,
системный `dotnet`, затем локальный `.tools/dotnet/dotnet`. Локальный SDK
не входит в Git. Настройки среды и пакеты первого запуска могут создаваться
в игнорируемой `.dotnet-home/`.

На Windows без POSIX shell:

```powershell
dotnet build Mosaic.slnx -c Release -m:1
dotnet run --project src/Mosaic.Cli -c Release -- run examples/dice.mos --explain
dotnet run --project tests/Mosaic.Tests -c Release
```

## Функциональное ядро

- [x] Именованные неизменяемые привязки `let`.
- [x] Рекурсия, взаимная рекурсия и безопасные для стека хвостовые вызовы.
- [x] Явные ленивые вычисления `delay` / `force` (call-by-name).
- [x] Функции как значения, частичное применение, функции высшего порядка.
- [x] Лексические замыкания без изменяемых ссылок.
- [x] Списки и ленивые потоки.
- [x] `map`, `filter`, `foldl`, `range`, `iterate` и другие библиотечные функции.
- [x] Чтение и запись текстовых файлов через явную границу CLI.

Дополнительно: произвольная точность целых чисел и дробей, `choose`, `observe`,
вероятность наблюдения (`evidence`), объяснения миров, JSON, REPL, позиции
ошибок и ограничения числа миров/шагов.

## Небольшие программы

Факториал и рекурсивное замыкание:

```lisp
(letrec [fact (fn [n]
               (if (= n 0) 1 (* n (fact (- n 1)))))]
  (fact 20))
```

Ленивый бесконечный поток:

```lisp
(stream-take 8 (iterate (fn [x] (* x 2)) 1))
```

Условная вероятность:

```lisp
(let [a (choose "a" [[1 0] [1 1]])
      b (choose "b" [[1 0] [1 1]])]
  (observe (> (+ a b) 0) a))
```

Здесь результат `0 @ 1/3`, `1 @ 2/3`, а `evidence = 3/4`.

## Проверки

`./scripts/verify.sh` собирает решение с предупреждениями как ошибками,
запускает 73 F#-проверки и отдельные сквозные проверки всех 12 примеров,
команд CLI, файлов, JSON, REPL и лимитов. Есть проверки 20 000 хвостовых и
10 000 нехвостовых вызовов, сетки рациональных тождеств и вероятностной массы.
GitHub Actions настроен на Ubuntu и macOS; локально проект проверен на macOS arm64.

## Устройство

```text
src/Mosaic.Core/   синтаксис, reader, значения, примитивы, CEK-машина, prelude
src/Mosaic.Cli/    аргументы команд, файлы, JSON и REPL
tests/            проверки семантики на F# без внешнего тестового фреймворка
examples/         12 запускаемых программ
scripts/          сборка и сквозные проверки
docs/             руководство, спецификация и материалы для защиты
ai/               исходное ТЗ и записи итераций разработки
```

В Core нет `mutable`, `ref`, изменяемых коллекций, глобального состояния или
файлового I/O. Машина передаёт новую конфигурацию и мир как значения. Prelude
написан на Mosaic, поэтому его функции проходят через ту же семантику.

## Границы реализации

Типизация динамическая; `check` проверяет только синтаксис. Язык по умолчанию
строгий, а явные задержки не мемоизируются. Точный перебор экспоненциален по
числу независимых выборов. Встроенных непрерывных распределений, компилятора,
системы модулей и браузерной IDE нет. Результат верхнего уровня должен быть
данными; функции и задержки нужно применить или форсировать. Подробнее — в
[спецификации](docs/language.md) и [семантике](docs/semantics.md).
