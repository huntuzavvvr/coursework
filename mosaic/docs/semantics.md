# Семантика и устройство

## Денотация

Обычная чистая функция возвращает значение. Выражение Mosaic интерпретируется
как чистое преобразование входного контекста и неизменяемого мира в конечный
список пар «значение, новый мир», либо диагностику. Эффекты выбора и наблюдения
явны в этой модели; выражения с `choose` нельзя описывать просто независимыми
распределениями без учёта таблицы уже сделанных решений.

Мир `W = (p, C, O)` содержит вес `p`, таблицу решений `C` и артефакты `O`.
Входной контекст `I` — неизменяемая таблица текстов. Начальный мир:
`(1, ∅, ∅)`.

Для нового ключа `k` и нормированного распределения `[(qᵢ,vᵢ)]`:

```text
choose(k, D), (p, C, O)
    ⇒ [(vᵢ, (p·qᵢ, C[k ↦ (D,vᵢ)], O))]
```

Если `C[k] = (D,v)`, то тот же вызов возвращает `v` и исходный мир. Если
распределение другое — диагностика. Идентичность распределения определяется
канонизацией значений и нормированных весов, а не порядком записи.

```text
observe(false, body), W ⇒ []
observe(true, body), W  ⇒ evaluate(body, W)
```

Для выживших миров `Wⱼ` с результатами `vⱼ`:

```text
Z = Σⱼ pⱼ                         вероятность наблюдения, evidence
P(v | observations) = Σⱼ:vⱼ=v pⱼ / Z
```

Все операции выполняются над дробями bigint, без округления float. Программа
с ошибкой в любом посещённом мире возвращает ошибку целиком: исключения не
маскируются под маловероятные или отклонённые сценарии.

## Поток обработки

```text
UTF-8 source
  → immutable reader → формы со Span → AST
  → добавление Prelude
  → CEK-машина: expression / environment / continuation
  → выжившие миры, артефакты и значения
  → объединение одинаковых результатов и нормализация
  → CLI: текст, JSON, явно запрошенные файлы
```

`Syntax.fs` определяет данные, позиции, AST и точные числа. `Reader.fs`
сначала читает S-выражения с позициями, затем проверяет специальные формы.
Позиция передаётся в неизменяемом cursor; стек разбора не хранится в mutable.

`Values.fs` задаёт значения и миры. `Primitives.fs` реализует арифметику,
канонизацию выбора, списки и логический I/O. `Machine.fs` — машину,
`Prelude.fs` — библиотеку на Mosaic, `Engine.fs` — публичный API.

## Продолжения вместо стека хост-языка

Конфигурация машины содержит `Control`, список `Frame`, `World` и текущий Span.
Кадры обозначают оставшуюся работу: выбрать ветвь, связать имя, вычислить
аргументы, собрать список, форсировать задержку. Один `step` возвращает
продолжения, готовое значение, отказ мира или диагностику.

`drive` хвосторекурсивно обходит список конфигураций. Ветвления добавляют новые
конфигурации к списку ожидающих; это поиск в глубину. Вызов функции переходит
к её телу, не вызывая рекурсивно host-eval. Поэтому хвостовая рекурсия не
накапливает ни машинные кадры, ни стек F#. Нехвостовая рекурсия хранит
продолжения в куче — она безопасна для host-стека, но использует память.

## Рекурсивные замыкания без циклов

`RecursiveClosure` хранит имя функции, описания всей группы и внешнее
окружение. При вызове создаётся новое окружение с замыканиями этой группы,
после чего добавляются аргументы. Замыкания ссылаются на прежнее внешнее
окружение, а не на изменяемую ячейку с собственным окружением. Получается
взаимная рекурсия без `ref`, `mutable` и циклической инициализации.

## Ленивость и ввод-вывод

`Suspended` хранит AST и лексическое окружение. `force` переходит к ним в
текущем мире. Кеш отсутствует: это call-by-name. Бесконечный поток конечен
как объект в памяти, потому что его хвост — описание дальнейшего вычисления.

`read-text` читает из `Context.Inputs`, заполненного CLI до запуска.
`write-text` возвращает текст и новый `World.Outputs`. В одном мире второй
раз можно записать то же значение под тем же именем, но нельзя заменить его
другим. Файлы создаёт только CLI по `--output`. Для экспорта требуется,
чтобы каждый выживший мир содержал одинаковый текст по данному имени.
Все проверки согласованности выполняются до первой записи; ошибки ОС при
записи нескольких файлов не обеспечивают транзакционного отката.

## Ограничения и сложность

- Полный перебор независимых выборов имеет экспоненциальное число миров:
  например, n бинарных событий могут дать 2ⁿ конфигураций.
- Вес нормируется в конце. Ключи и артефакты хранятся в persistent Map;
  поиск/добавление имеет логарифмическую стоимость по числу ключей, не считая
  стоимости сравнения ключей. Дробная арифметика зависит от длины bigint.
- Отдельные миры не сливаются во время вычисления: это сохраняет объяснения,
  но расходует память. Объединяются лишь итоговые наблюдаемые значения.
- `MaxSteps` ограничивает все переходы, `MaxWorlds` — накопленное количество
  созданных сценариев (начальное 1, при разветвлении на k добавляется k−1).
  Отброшенные сценарии бюджет не возвращают.
- Поиск в глубину не справедлив для бесконечных ветвей: лимит останавливает
  всю программу без частичного распределения. Корректный точный ответ требует
  завершения всех достижимых ветвей в пределах бюджета.
- Разбор ограничивает синтаксическую вложенность 256 уровнями. Лимиты машины
  не являются полной песочницей по памяти или времени отдельной bigint-операции.
- Источник ошибки библиотечной функции может ссылаться на строку Prelude;
  полноценного многофайлового стека источников пока нет.

Детерминированное ядро имеет лямбды, неограниченные в математической модели
натуральные числа и общую рекурсию; этим можно выразить универсальное
вычисление. Конкретный исполняемый интерпретатор намеренно ограничен ресурсами.

## Связь с другими работами

Лямбда-исчисление, S-выражения, машины продолжений и вероятностное
программирование — известные идеи. Например,
[Church (Goodman et al., 2008)](https://proceedings.mlr.press/r6/goodman08a.html)
связывает функциональный язык и условные распределения по историям вычисления.
Mosaic — самостоятельная учебная реализация с небольшим точным конечным
перебором, явными строковыми ключами корреляции и объяснениями. Это
содержательное проектное решение, но не заявление о первом таком языке.
