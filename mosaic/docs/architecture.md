# Архитектура интерпретатора

[Главная](index.md) · [Синтаксис](syntax.md) · [API](api.md) · [Примеры](examples.md)

## Общая схема

```text
Текст программы
      ↓
Reader: чтение форм и построение AST
      ↓
Interpreter: рекурсивная функция eval
      ↓
Значения и сценарии
      ↓
Engine: объединение результатов и вероятностей
      ↓
CLI: вывод результата и запись файлов
```

## AST и парсер

`Syntax.fs` задаёт узлы AST: литерал, имя, функция, вызов, привязка, рекурсия,
условие, список, задержка и наблюдение. Каждый узел хранит позицию в исходнике.
Там же определены данные и рациональные числа на основе `bigint`.

`Reader.fs` сначала читает скобочные формы, затем распознаёт специальные
конструкции и строит AST. Текущая позиция передаётся аргументом функции.
Один файл содержит одно выражение; лишний текст после него считается ошибкой.

## Значения и окружения

`Values.fs` содержит типы значений. Функция представлена замыканием: список
параметров, тело и окружение определения. Окружение — `Map<string, Value>`.
Добавление имени создаёт новое окружение, не меняя старое.

`RecursiveClosure` хранит описание группы рекурсивных функций и внешнюю среду.
При вызове интерпретатор добавляет функции этой группы в среду, затем связывает
параметры. Поэтому для рекурсии не нужна изменяемая ссылка на собственное замыкание.

## Вычисление выражений

В `Interpreter.fs` используется обычный рекурсивный обход:

```text
eval depth environment world expression → список (value, world)
```

Литерал возвращает значение, имя ищется в окружении, лямбда создаёт замыкание.
Для вызова вычисляются функция и её аргументы, после чего выполняется тело
в расширенном окружении. `if` вычисляет только выбранную ветвь.

Например, `(let [x 5] (+ x 2))`:

1. Вычислить литерал `5`.
2. Создать окружение, в котором `x` связан с `5`.
3. Найти функцию `+`, вычислить аргументы `x` и `2`.
4. Применить сложение и получить `7`.

Возвращается список результатов, потому что внутри выражения может встретиться
`choose`. Вспомогательная функция `collect` продолжает вычисление для каждой
ветви и объединяет результаты. Обычно ветвь одна, поэтому обычная программа
работает как в стандартном интерпретаторе.

## Сценарии и вероятности

Сценарий хранит три вещи: текущую вероятность, таблицу сделанных выборов и
логические выходные тексты. Все три поля неизменяемы.

Новый `choose` создаёт по сценарию для каждого варианта и умножает исходный
вес на вероятность варианта. Повторный ключ берёт уже выбранное значение,
не меняя вес. `observe false` возвращает пустой список — эта ветвь исключается.

В `Engine.fs` одинаковые результаты объединяются. Сумма весов оставшихся
сценариев — `evidence`. Условная вероятность результата равна его суммарному
весу, делённому на `evidence`. Если сумма равна нулю, наблюдение невозможно.
Для арифметики используются точные дроби, поэтому округления нет.

## Библиотека, ленивость и файлы

`Primitives.fs` содержит арифметику, операции со списками, выборы и логический
I/O. `Prelude.fs` задаёт `map`, `filter`, `foldl` и другие функции на Mosaic.

Задержка хранит тело и окружение. `force` вычисляет их в текущем сценарии;
кеша нет. Это позволяет описать бесконечный поток через отложенный хвост.

Файлы читает и записывает только `Program.fs` в CLI. Интерпретатор получает
готовую таблицу входных текстов и возвращает таблицы выходных текстов.
Перед записью проверяется согласие всех оставшихся сценариев. Несколько
физических записей не образуют транзакцию: ошибка ОС не откатывает уже записанный файл.

## Ошибки и ограничения

Внешний API возвращает `Result<Report, Diagnostic>`. Внутри рекурсивного
интерпретатора для выхода с ошибкой используется закрытое исключение,
перехватываемое в `run`. В диагностике есть код, сообщение, строка и столбец.
Ошибка в достижимом сценарии завершает всю программу, а не отбрасывает сценарий.

Интерпретатор использует стек F#; оптимизация хвостовых вызовов языка не
реализована. Вложенность eval ограничена 256 уровнями, размер каждого
промежуточного списка — 1024 сценариями. Это не общий счётчик выполненной
работы и не полная защита от долгих вычислений или расхода памяти.
Перебор независимых событий в худшем случае экспоненциален.

## Как добавить функцию

Для простой операции нужно добавить её число аргументов в `Primitives.arities`,
ветку обработки в `Primitives.invoke` и тест. Если функция выражается через
готовые операции, достаточно добавить определение в Prelude и проверить его.
Изменять парсер требуется только для новой специальной формы.
