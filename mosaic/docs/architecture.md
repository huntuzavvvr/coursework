# Устройство интерпретатора

[Документация](index.md) · [Синтаксис](syntax.md)

## Этапы выполнения

```text
Исходный текст → Reader → AST → Interpreter → значение и тексты выходов
                                  ↑                    ↓
                          Prelude, Primitives         CLI
```

`Reader` разбирает текст. `Prelude` добавляет определения стандартной библиотеки.
`Interpreter` вычисляет выражение, а `Engine` преобразует итоговое значение
в данные, которые можно вывести. `Program.fs` содержит точку входа CLI:
читает аргументы запуска, загружает входные файлы и записывает результат.

Файлы языка лежат в папке `core/`, `Program.fs` — в корне. Они собираются
одним проектом `Mosaic.fsproj`.

## Представление программы

В `Syntax.fs` описаны типы `Expr` и `Node`. Узлы дерева соответствуют литералам,
именам, функциям, вызовам, привязкам, условию, спискам, цепочкам и отложенным
выражениям. У каждого узла есть диапазон в исходном тексте для сообщений об ошибках.

`Reader.fs` сначала читает атомы и группы скобок, затем преобразует их в AST.
Позиция передаётся неизменяемой записью. Специальные формы проверяются во время
разбора: например, параметры функции должны быть уникальны, а `letrec` принимает
только функции.

## Значения и окружения

`Value` представляет данные, списки, замыкания, встроенные функции и отложенные
выражения. Числа хранятся как `bigint`. Окружение — `Map<string, Value>`:
добавление привязки создаёт новое окружение, доступное только соответствующей
части вычисления.

Замыкание хранит параметры, тело и окружение определения. При вызове аргументы
добавляются именно к этому окружению. Поэтому переменная из вызывающего кода
не подменяет захваченную переменную.

Рекурсивное замыкание хранит имя функции, описания всех функций группы `letrec`
и внешнее окружение. При вызове окружение группы восстанавливается из описаний.
Циклическая ссылка на изменяемый словарь не нужна.

## Вычисление выражений

Основная функция `eval` рекурсивно разбирает узел AST и возвращает пару:
значение и таблицу подготовленных файловых выходов. Аргументы и списки
вычисляются слева направо. Привязки `let` расширяют окружение по очереди.

Вызов обрабатывает `apply`. Для замыкания он связывает параметры с аргументами
и вычисляет тело. При нехватке аргументов возвращается новое замыкание;
для встроенной функции сохраняется список уже переданных аргументов.

`pipe` сначала вычисляет начальное значение. Затем `List.fold` проходит по
шагам: вычисляет функцию шага и передаёт ей текущий результат. Здесь используются
те же правила вызова, что и в обычном выражении. Отдельной системы типов или
особых правил для функций цепочки нет.

`delay` сохраняет выражение и окружение. `force` запускает его вычисление без
кеширования. `if` вычисляет только одну ветвь.

## Библиотека и файловые операции

Встроенные операции находятся в `Primitives.fs`. Функции `map`, `filter`,
`foldl` и остальные написаны на Mosaic в `Prelude.fs`. Библиотека использует
рекурсию и функции высшего порядка так же, как пользовательская программа.

Ядро не обращается к файловой системе. `Context.Inputs` содержит тексты входов,
`Report.Outputs` — тексты выходов. Изменений общей памяти при вычислении нет:
таблица выходов передаётся дальше как новое значение. Фактические чтение,
запись и печать сосредоточены в CLI.

## Ошибки и ограничения

Внутри парсера и вычислителя используются закрытые типы исключений, чтобы
прервать рекурсивный обход при ошибке. На внешней границе они преобразуются
в `Result<_, Diagnostic>`. Диагностика содержит код, сообщение и позицию.

Глубина разбора и вычисления ограничена 256 уровнями. Это ограничение
учебного рекурсивного интерпретатора; оптимизации хвостовых вызовов нет.
Стандартная библиотека разбирается при каждом запуске. При ошибке внутри её
функции позиция может относиться к тексту библиотеки, полного стека вызовов нет.

## Проверки

В `examples/` находятся семь программ: факториал, замыкания, обработка списков,
цепочка преобразований, оценки, ленивый поток и файловый ввод-вывод.
Ожидаемые результаты приведены в [описании примеров](examples.md).

Примеры можно запустить локально через `dotnet run -- examples/имя.mos`; для файлового примера
нужно передать пути через `--input` и `--output`.
