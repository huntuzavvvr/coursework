# Материалы для защиты

## Демонстрация на 7–10 минут

1. Сформулировать задачу: программа должна описывать неопределённость и
   сохранять связь между повторными обращениями к одному событию.
2. Запустить `shared-weather.mos --explain`. Объяснить отсутствие смешанных
   пар и то, почему вес не умножается дважды.
3. Запустить `detective.mos --explain`. На бумаге получить `9/50` и `1/2`.
4. Показать факториал, замыкание и частичное применение в `closures.mos`.
5. Показать бесконечный поток Фибоначчи и ограниченный `stream-take`.
6. Открыть `Machine.fs`: указать конфигурацию, кадры и хвосторекурсивный drive.
7. Показать `RecursiveClosure` и объяснить, почему не нужен ref.
8. Запустить `./scripts/verify.sh`, затем назвать ограничения реализации.

## Вопросы, на которые нужно уметь ответить

**Чем язык отличается от Lisp с новыми словами?**
S-выражения выбраны только для простого разбора. Новое поведение проекта —
именованные события, точные ветвления, условные распределения и объяснения.
Например, одинаковый ключ даёт корреляцию, два разных ключа — независимость.

**Почему реализация функциональная, если мир меняется?**
Мир не меняется на месте: следующий шаг возвращает новое значение записи с
новыми persistent Map. Это явная передача состояния, допускающая ветвление
без общей изменяемой памяти. И/O в CLI отделён от вычисления.

**Почему нельзя нормировать после каждого observe?**
Нужно сохранить веса всех выживших историй относительно исходной модели.
Локальная нормализация внутри одной ветви может потерять информацию об
относительной вероятности попадания в эту ветвь. В Mosaic суммирование и
нормализация происходят один раз в конце.

**Как устроена рекурсия без циклической ссылки?**
Замыкание хранит описание группы и внешнюю среду. Вызов заново расширяет эту
среду именами той же группы, затем параметрами. Никакую ячейку с указателем
на себя обновлять не приходится.

**Где хранятся незаконченные вычисления?**
В списке кадров продолжений. Например, для `(+ 1 (f n))` кадр хранит работу
после возврата `f`. Хвостовой вызов такой дополнительной работы не требует.

**Call-by-name или call-by-need?**
Первое. Повторный force повторяет тело. Внутри отложенного выбора совпадение
результата обеспечивается таблицей событий, не кешем thunk. Это различие
проверяется тестами и явно указано в документации.

**Язык полон по Тьюрингу?**
Его детерминированное математическое ядро допускает общую рекурсию, лямбды и
неограниченные натуральные числа. Реальная программа имеет ограничения
памяти и настроенные бюджеты. Точность вероятностей не означает разрешимости
проблемы остановки или завершения любого запроса.

**Почему не использовать float и генератор случайных чисел?**
Задача — точное объяснимое перечисление небольших конечных моделей. Дроби
bigint сохраняют равенства и evidence. Цена — рост чисел и числа миров;
для больших моделей понадобился бы другой механизм вывода.

**Что произойдёт при ошибке только в одном мире?**
Вся программа вернёт диагностику. Иначе ошибка могла бы незаметно изменить
распределение. Отбрасывать миры разрешено только явным observe.

**Можно ли записать разные файлы из разных миров?**
Каждый мир формирует собственные логические артефакты. CLI экспортирует
имя только при одинаковом тексте во всех выживших мирах. Неоднозначность
является ошибкой экспорта, а не недетерминированной перезаписью.

## Практические задания для понимания

- До запуска предсказать `(+ (choose "x" [[1 0] [1 1]]) (choose "x" [[1 0] [1 1]]))`.
- Заменить второй ключ и объяснить появление результата `1`.
- Реализовать функцию длины списка без встроенного `length`.
- Добавить в prelude `scanl` и тест для неё.
- Найти кадр машины, отвечающий за частичное применение и избыток аргументов.
- Объяснить, почему `./mosaic check` может принять программу с неизвестным именем.

Описание использованных инструментов и процесса разработки находится в AI_USAGE.md.
